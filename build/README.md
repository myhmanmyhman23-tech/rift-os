# ISO сборка RIFT OS

Текущий профиль: **0.2.0-alpha.1**, Kubuntu 24.04.5 LTS x86_64. Первый образ экспериментальный. Наличие скриптов не означает, что образ уже собран: результатом сборки служат ISO, журнал QEMU и контрольные суммы в GitHub Release.

## Что происходит

1. Скачивается конкретный официальный ISO, SHA-256 сверяется с зафиксированным значением из `base.env`.
2. Извлекается единственная файловая система Casper. Неизвестная многослойная схема приводит к остановке.
3. Устанавливаются Node.js, диагностические и графические пакеты и четыре приложения Flatpak: Modrinth App, Steam, Lutris, Bottles.
4. Добавляются центр RIFT OS, автоматическое открытие при входе, оформление KDE и фоновая подготовка драйверов при первом запуске установленной системы.
5. Файловая система пересобирается. Обновляются размер, пакетный манифест и MD5-список файлов носителя. Xorriso воспроизводит исходную конфигурацию загрузки; ядро и initramfs сохраняются.
6. Проверяются записи загрузки BIOS/UEFI. QEMU загружает ядро с нового live-образа и проверяет центр и наличие лаунчеров.
7. ISO разделяется на части менее 2 ГБ. Готовятся SHA256SUMS, скрипты сборки частей и журналы проверки.

Прямой запуск ядра в QEMU **не подтверждает** выполнение загрузчика, работу графического рабочего стола, установку на диск и совместимость игр. Эти проверки выполняются отдельно перед стабильным релизом.

## Сборка на GitHub

Рабочие процессы находятся в `.github/workflows/`. После загрузки кода каждый тег вида `v<версия из package.json>` запускает сборку и публикует **prerelease** только при успешных проверках. Пример: `v0.2.0-alpha.1`.

Можно вручную запустить **Actions → Build RIFT OS ISO → Run workflow**. Без `publish` образ сохраняется как временный артефакт на один день, с `publish` создаётся prerelease. Опубликованные версии не перезаписываются.

Для новой версии нужно изменить `package.json`, заметки `release/NOTES.md`, описание интерфейса при необходимости и создать новый тег. Скрипты подготовки не содержат GitHub-паролей или личных токенов; workflow использует встроенный GITHUB_TOKEN.

## Локальная Linux-сборка

Нужен x86_64 Linux, root, Node.js 18+, Python 3.11+, минимум **40 ГБ свободно на /mnt** и доступ к интернету. Рекомендуемая система сборки — Ubuntu 24.04.

```sh
sudo apt-get install xorriso squashfs-tools qemu-system-x86 curl nodejs python3
bash build/build-iso.sh --plan
sudo bash build/build-iso.sh
```

Скрипт создаёт рабочую папку `/mnt/rift-build.XXXXXX`, снимает временные монтирования при завершении и оставляет папку для анализа. Кеш исходного ISO находится в `build/cache`, результаты — в `dist`. Для экономии места удалить рабочую папку можно после успешного завершения и проверки отсутствия монтирований.

## Драйверы

Mesa и графические библиотеки входят в образ. NVIDIA определяется **на целевом установленном компьютере**, а не на машине сборки. `rift-driver-prepare.service` устанавливает рекомендованный Ubuntu драйвер; для этого нужен интернет. Не отключается Secure Boot и не выполняется автоматическая перезагрузка. В live-сессии служба пропускает установку драйвера.

Состояние сохраняется в `/var/lib/rift-os/driver-status.json`; подробности — `journalctl -u rift-driver-prepare`. При ошибке подготовка повторяется на следующей загрузке. Последовательность установки NVIDIA, Secure Boot и обновления Flatpak ещё требует испытаний на физическом оборудовании.

Modrinth используется через поддерживаемую сообществом сборку Flatpak. Пользователь входит в собственный лицензированный Microsoft-аккаунт. Пароли не сохраняются игровым центром.
